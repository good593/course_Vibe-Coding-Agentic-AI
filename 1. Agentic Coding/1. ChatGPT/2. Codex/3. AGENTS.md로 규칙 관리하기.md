# 3. AGENTS.md로 규칙 관리하기

## 새 채팅에서도 같은 개발 규칙 유지하기

시작: 2장 계획 파일과 1장 추천 코드

결과: 프로젝트 지침 + 사용자 프로필 + SQLite 마이그레이션

---

## 먼저 경험할 문제

새 요청마다 다음 조건을 반복하고 있습니다.

- uv로 실행하기
- 화면에서 DB에 직접 접근하지 않기
- 기존 데이터와 원본 CSV 보존하기
- 테스트와 diff를 확인하기

한 작업의 조건은 프롬프트에, 계속 적용할 규칙은 파일에 둡니다.

---

## 단계 1. 반복한 규칙 추출

Codex의 새 채팅에서 요청합니다.

```text
README.md와 docs/plans/02-profile-migration.md를 읽어줘.
이번 기능에만 해당하는 조건과 앞으로도 유지할 개발 규칙을
구분해서 제안해줘. 아직 코드를 수정하지 마.
```

“프로필 API 경로”와 “SQL은 저장소 계층에 둔다”의 차이를 설명합니다.

---

## 단계 2. AGENTS.md 작성

```text
방금 정리한 지속 규칙을 project 루트의 AGENTS.md로 작성해줘.
실제 프로젝트 구조와 uv 실행·테스트 명령을 확인해서 반영해줘.
API 키, 개인정보, 모델이 추측한 비즈니스 규칙은 넣지 마.
현재 없는 도구나 명령을 있다고 쓰지 마.
```

생성 위치는 현재 작업 폴더의 `AGENTS.md`입니다.
이 파일은 Codex가 프로젝트 작업에 참고하는 지침입니다.

---

## 지침 내용 예시: 구조와 실행

````markdown
# 프로젝트 작업 규칙
- frontend는 FastAPI만 호출한다.
- API는 요청/응답, services는 업무 규칙, repositories는 SQL을 담당한다.
- 패키지 관리는 uv를 사용하고 의존성 변경 시 uv.lock도 갱신한다.
- 실행 방법은 README.md를 따른다.
## 검증
```powershell
uv run --locked python -m pytest -q
uv run --locked ruff check .
uv run --locked ruff format --check .
```
````

---

## 지침 내용 예시: 데이터와 완료 조건

```markdown
## 데이터 변경
- ../data와 ../docs의 원본 자료를 수정하지 않는다.
- 누락 수치를 0으로 대체하거나 근거·함량을 추정하지 않는다.
- 기존 DB를 지우지 말고 명시적 마이그레이션으로 변경한다.
- 변경 전 백업과 변경 후 데이터 보존 검증을 수행한다.
## 완료 보고
- 변경 파일, 요구사항ID, 실행 명령과 결과를 보고한다.
- 실제 실행과 모의 테스트, 미실행 항목을 구분한다.
- .env, 비밀키, 개인의 건강정보를 커밋하거나 출력하지 않는다.
```

---

## 단계 3. 적용 여부 확인

새 채팅을 시작해 요청합니다.

```text
이번 프로젝트에서 적용되는 지침 파일의 경로와 핵심 규칙을
정리해줘. 현재 작업 위치도 확인해줘. 아직 수정하지 마.
```

전역 지침과 상위 폴더 지침도 영향을 줄 수 있습니다.
원하는 규칙이 없으면 작업 위치·파일 이름·상위 override를 확인합니다.
AI의 요약만 믿지 말고 다음 작업의 파일 배치와 실행 명령도 봅니다.

---

## 단계 4. 계획을 인계하고 구현

```text
docs/plans/02-profile-migration.md의 검토된 계획을 구현해줘.
AGENTS.md를 적용하고 먼저 기존 테스트를 확인해줘.
sqlite3 백업 API를 사용하는 scripts/backup_db.py를 만들고,
현재 DB를 var/backups에 이름이 겹치지 않게 백업해줘.
적용 이력을 기록하는 버전별 마이그레이션을 구현해줘.
프로필 API와 화면을 추가하고 기존 데이터가 보존됐는지 검증해줘.
```

실행 중 파일 배치·백업 경로·새 테스트를 확인합니다.

---

## 단계 5. 마이그레이션의 재실행 검증

```text
scripts/migrate_db.py를 모듈 실행 가능한 진입점으로 제공해줘.
적용한 버전은 다시 실행하지 않고, 중간 실패는 롤백되게 해줘.
새 DB뿐 아니라 0장 스키마의 데이터가 있는 DB를 테스트에 사용해줘.
상품/기능성/섭취기준의 모든 원본 필드가 유지되는지 비교해줘.
```

구현된 뒤 실행합니다.

```powershell
uv run --locked python -m scripts.migrate_db
uv run --locked python -m scripts.migrate_db
```

---

## 단계 6. API와 화면 확인

| 확인 | 기대 결과 |
| --- | --- |
| 유효한 프로필 생성 | 201, 서버가 생성한 ID |
| 생성한 프로필 조회 | 입력 조건과 일치 |
| 없는 ID 조회 | 404 |
| 기준표에 없는 조합 | 422 |
| 상품 조회·추천 | 기존 동작 유지 |
| 마이그레이션 재실행 | 중복 적용 없음 |

이 단계의 가상 프로필 ID는 인증 수단이 아닙니다.
실제 사용자 접근 제어는 9장에서 별도로 구현합니다.

---

## 단계 7. 반복 실수를 규칙으로 보완

```text
이번 작업에서 내가 다시 설명해야 했던 조건은 [관찰한 내용]이야.
AGENTS.md에 이미 있는 규칙인지 확인하고,
없는 지속 규칙이면 짧게 추가해줘. 이번 작업에만 필요한 내용은
계획 문서에 남겨줘. 중복 규칙을 길게 추가하지 마.
```

반복 실수가 없으면 억지로 규칙을 추가하지 않습니다.
