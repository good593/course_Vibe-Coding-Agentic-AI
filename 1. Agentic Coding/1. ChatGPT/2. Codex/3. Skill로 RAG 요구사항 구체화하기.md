# Codex의 Skill이란?
- 특정 작업을 반복해서 수행할 수 있도록 작업 절차와 참고 자료를 묶어 둔 패키지입니다. 
- 핵심 파일은 `SKILL.md`이며, 필요하면 `실행 스크립트`와 `템플릿`도 함께 넣습니다.

> 즉, 반복해서 입력하던 작업 지침을 저장하고 재사용하는 것입니다.

| 활용 목적 | 설명 |
|---|---|
| 반복 지시 줄이기 | 매번 긴 작업 절차를 입력할 필요가 줄어듦 |
| 작업 방식 통일 | 정해 둔 순서와 기준에 따라 작업하도록 안내 |
| 노하우 공유 | 팀의 리뷰 기준이나 문서 작성 방식을 함께 사용 |
| 자료 활용 | 참고 문서, 템플릿, 스크립트를 작업에 연결 |

---
## Skill은 무엇으로 구성되나요?
> SKILL.md는 필수이며 나머지 자료는 선택 사항입니다. 
> 마크다운 지침만으로도 스킬을 만들 수 있습니다.

| 구성 요소 | 역할 | 필수 여부 |
|---|---|---|
| `SKILL.md` | 이름, 설명, 작업 절차 | 필수 |
| `references/` | 참고 문서와 상세 기준 | 선택 |
| `scripts/` | 반복 작업에 사용할 실행 코드 | 선택 |
| `assets/` | 템플릿과 리소스 | 선택 |

---
## Codex는 Skill을 어떻게 사용하나요?

| 방식 | 설명 | 예시 |
|---|---|---|
| 명시적 사용 | 사용자가 스킬을 직접 지정 | `$code-review 변경 사항을 검토해줘.` |
| 자동 선택 | 요청과 스킬 설명이 일치하면 Codex가 선택 | `이번 변경 사항에서 오류 가능성을 검토해줘.` |

> Codex CLI와 IDE 확장에서는 `/skills` 또는 `$`로 스킬을 선택할 수 있습니다. 자동 선택 여부는 스킬 설명과 호출 정책에 영향을 받습니다.

---
## 각각의 역할 및 의미 

| 구분 | 답하는 질문 | 예시 |
|---|---|---|
| **프롬프트** | 지금 무엇을 해줄까? | “로그인 오류를 수정해줘.” |
| **AGENTS.md** | 이 프로젝트에서는 어떤 규칙을 지킬까? | “Python 코드에는 타입 힌트를 작성한다.” |
| **Skill** | 이 종류의 작업을 어떤 절차로 할까? | “코드 리뷰 시 변경 확인 → 문제 분석 → 수정 제안” |
| **config.toml** | Codex를 어떤 환경과 설정으로 실행할까? | 모델, 샌드박스, 승인 정책 설정 |

> `AGENTS.md`에 프로젝트의 공통 규칙을 작성하고, `Skill`에는 코드 리뷰처럼 특정 작업의 상세 절차를 작성하는 방식

---
## 저장되는 위치 

| 위치 | 역할 |
|---|---|
| `프로젝트/.codex/config.toml` | 해당 프로젝트의 Codex 설정 |
| `프로젝트/AGENTS.md` | 해당 프로젝트의 작업 규칙 |
| `프로젝트/.agents/skills/` | 해당 프로젝트의 스킬 |

> `.codex/config.toml`은 실행 설정, `AGENTS.md`는 작업 규칙, `.agents/skills/`는 재사용할 작업 절차를 저장하는 위치입니다.

# Skill로 RAG 요구사항 구체화하기

## find-skills와 grill-me를 개발 작업에 사용하기

시작: 2장 지침·설정 적용, 상품 조회 정상

결과: 사용한 Skill 기록 + 합의한 RAG 상담 요구사항

---

## 이번에 사용할 두 Skill

| Skill | 이번 작업에서 할 일 |
| --- | --- |
| find-skills | 필요한 Skill을 찾고 출처·설치 방법 확인 |
| grill-me | 질문으로 상담 범위와 완료 조건 구체화 |

Skill 개념·제작·예약은 [Work 자료](<../1. Work/README.md>)를 참고합니다.
이번 장에서는 기존 Skill의 설치·호출·결과 확인을 실습합니다.
아직 RAG 코드를 구현하지 않습니다.

---

## 단계 1. 시작 도구와 상태 확인

project 터미널에서 실행합니다.

```powershell
# 설치·검색에 사용할 Node.js와 npm 도구를 확인합니다.
node --version
npm --version
npx --version
# 현재 브랜치와 남은 변경을 확인합니다.
git status --short --branch
```

2장의 chore/codex-setup 브랜치에서 준비를 이어갑니다.
Node.js 도구가 없으면 강사의 사전 준비 안내를 따릅니다.

---

## 단계 2. find-skills 원문 확인과 설치

[Vercel Labs 원문](https://github.com/vercel-labs/skills/blob/main/skills/find-skills/SKILL.md)을 읽습니다.

```powershell
# 저장소의 Skill 이름을 조회합니다. 설치하지 않습니다.
npx skills add vercel-labs/skills --list
# Codex 프로젝트용으로 find-skills만 복사 설치합니다.
npx skills add vercel-labs/skills --skill find-skills --agent codex --copy
# Codex가 사용할 설치 목록을 확인합니다.
npx skills list --agent codex
```

개인 전역 설치 대신 프로젝트 범위를 선택합니다.
설치 결과의 경로·잠금 파일·원본 출처를 확인합니다.

---

## 단계 3. find-skills로 검색

Codex 입력창에서 $를 입력해 find-skills를 선택합니다.

```text
$find-skills
구현 전에 요구사항과 모호한 설계 결정을 인터뷰로 정리하는
Skill을 찾아줘. 후보의 출처·역할·호출 조건을 비교해줘.
grill-me도 확인하고 아직 새 Skill을 설치하지 마.
검색·원문 확인을 실제로 수행했는지도 알려줘.
```

검색 결과와 다운로드할 원문을 구분합니다.
필요한 역할에 맞는지 확인하고 grill-me를 선택합니다.

---

## 단계 4. grill-me와 의존 Skill 설치

현재 [grill-me 원문](https://github.com/mattpocock/skills/blob/main/skills/productivity/grill-me/SKILL.md)은 grilling을 호출합니다.
두 Skill의 본문을 확인한 뒤 함께 설치합니다.

```powershell
# 현재 저장소에 있는 이름을 먼저 확인합니다.
npx skills add mattpocock/skills --list
# 인터뷰 진입점과 실제 질문 절차를 함께 설치합니다.
npx skills add mattpocock/skills --skill grill-me --skill grilling --agent codex --copy
```

본문이 바뀌었으면 현재 의존성을 따릅니다. 저장소 전체를 설치하지 않습니다.
강사는 확인한 버전과 설치 결과를 수업 전에 기록합니다.

---

## 설치 경로와 호출 확인

```powershell
# 실제 설치된 Skill 폴더를 확인합니다.
Get-ChildItem -LiteralPath .agents/skills
# 이 이름으로 설치되었을 때 인터뷰 지침을 읽습니다.
Get-Content -LiteralPath .agents/skills/grill-me/SKILL.md
Get-Content -LiteralPath .agents/skills/grilling/SKILL.md
```

Codex에서 $ 선택 목록에 나타나는지 확인합니다.
안 보이면 실제 경로·메타데이터를 확인하고 확장을 재시작합니다.
원문의 /grill-me 표기와 Codex의 $ 호출을 구분합니다.

---

## 단계 5. 요구사항 맥락 조사

```text
../docs/요구사항정의서.xlsx의 RAG_구현범위,
../docs/데이터 정의서.xlsx의 RAG_문서와 RAG_API,
../docs/RAG 구현 명세.md와 ../docs/RAG 상담 요구사항 초안.md를 읽어줘.
현재 Settings와 integrations/llm.py도 확인해줘.
구현된 것, 정해진 계약, 학생이 결정할 질문을 구분해줘.
읽지 못한 파일은 추정하지 말고 알려줘. 아직 수정하지 마.
```

Excel 읽기 도구가 없으면 같은 범위를 설명한 실습 명세를 먼저 읽고,
정의서의 해당 시트는 학생이 직접 대조합니다.

## 짧은 아이디어를 전달하기

```text
상품 목록 옆에서 영양제 관련 질문을 할 수 있는 상담 챗봇을
추가하고 싶어. 검수한 문서를 검색하고 Groq로 답을 만들며
출처를 함께 보여줘야 해.
로그인·상담 이력 저장·복용량 계산은 이번 범위에서 제외할게.
```

대상 질문, 근거가 부족한 경우, 화면과 완료 기준이 아직 모호합니다.
이 부분을 다음 인터뷰에서 결정합니다.

---

## 단계 6. grill-me로 인터뷰

```text
$grill-me
방금 조사한 자료를 기준으로 RAG 상담 첫 버전의 요구사항을
구체화하도록 질문해줘. 코드에서 확인할 사실은 직접 조사하고,
내가 결정할 조건에는 추천안과 이유를 함께 제시해줘.
공통 API 계약을 유지하면서 사용자·상담 주제·문서 선정·화면·
근거 부족·장애 처리·완료 기준을 정리해줘.
합의할 때까지 구현하지 마. 질문과 내 답변을 구분해서 기록해줘.
```

답변이 앞선 결정에 의존하면 그 결정 후에 질문합니다.
원문의 질문 방식에 따라 답하고 미결 사항을 확인합니다.

---

## 인터뷰에서 확인할 결정

| 질문 | 필요한 결정 |
| --- | --- |
| 어떤 질문을 받는가? | 대상 질문 3개·제외 질문 2개 |
| 무엇을 검색하는가? | 원문 자료·검수 담당·준비 상태 |
| 답을 못 찾으면? | 부족 안내·사용자의 다음 행동 |
| 이전 대화를 사용하는가? | 단일 질문 처리·세션 표시 범위 |
| 장애와 출처를 어떻게 보여주는가? | 화면 상태와 인용 표시 |

검색 엔진·파일 배치는 다음 장에서 계획합니다.

---
## 성공뿐 아니라 경계·실패도 정하기

| 상황 | 공통 기대 결과 |
| --- | --- |
| 유효한 질문·근거 있음 | 200 answered + 인용 |
| 검색 결과 없음 | 200 insufficient_evidence, 생성기 미호출 |
| 문단은 있지만 답을 뒷받침하지 못함 | 200 insufficient_evidence |
| 빈 값·1000자 초과 | 422 |
| API 장애·잘못된 생성/인용 | 503 unavailable |

UI 안내 문구와 완료 확인 방법까지 인터뷰에서 합의합니다.

---
## 단계 7. 합의한 요구사항 저장

인터뷰 요약을 읽고 합의 여부를 확인한 뒤 요청합니다.

```text
합의한 요구사항을 docs/requirements/rag-chatbot.md에 작성해줘.
../docs/templates/rag-requirements.md의 형식을 사용해줘.
결정과 이유, 대상/제외 질문, 근거 문서 준비 상태,
실습ID별 완료 기준, 미결 질문을 포함해줘.
미결 조건이나 추천안을 확정된 요구사항으로 쓰지 마.
애플리케이션 코드는 아직 변경하지 마.
```

실제 공식 자료가 없으면 자료 준비를 미완료 항목으로 남깁니다.

## 단계 8. Skill과 문서의 변경 확인

```text

버전 식별 정보가 있으면 docs/lab-notes/03-skills.md에 기록해줘.
인터뷰 전후에 명확해진 조건과 미결 질문도 적어줘.
커밋 후보 파일을 제시해줘. 아직 커밋하지 마.
```

```powershell

git status --short
# 추적된 파일의 변경을 확인합니다.
git diff --stat
```
