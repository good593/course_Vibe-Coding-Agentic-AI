# 4. Codex 설정 활용하기

## 작업 규칙과 실행 환경을 구분하기

시작: 3장 완료, AGENTS.md와 SQLite 백업 보유

결과: 프로젝트 설정 기록 + Groq 연결 점검

---

## 먼저 경험할 문제

“파일을 읽기만 해 줘”라는 지시와 파일 쓰기 권한은 별개입니다.
작업 폴더나 실행 환경이 다르면 같은 요청도 다른 결과가 납니다.

| 위치 | 역할 |
| --- | --- |
| `AGENTS.md` | 프로젝트에서 지킬 작업 규칙 |
| `.codex/config.toml` | Codex의 프로젝트 설정 |
| `.env` | 우리 서비스의 DB·Groq 연결 설정 |

Groq는 **만드는 서비스의 AI API**이며 Codex 모델 설정과 다릅니다.

---

## 단계 1. 현재 환경 기록

```text
현재 작업 폴더, 프로젝트 실행 명령, 적용 중인 지침을 확인해줘.
확인할 수 있는 Codex 설정 파일의 위치만 알려줘.
.env 값과 토큰은 출력하지 마.
설정값을 실제로 확인할 수 없다면 추측하지 말고 확인 방법을 알려줘.
```

Codex 확장의 설정 메뉴에서 설치 버전과 선택한 모델을 확인합니다.
`docs/lab-notes/04-settings.md`에 비밀값 없이 기록합니다.

---

## 단계 2. 설정 파일 열기

Codex 확장 오른쪽 위 톱니바퀴에서
**Codex Settings → Open config.toml**을 찾습니다.

개인 기본값은 `~/.codex/config.toml`에 있습니다.
이번 실습은 `project/.codex/config.toml`을 사용합니다.

이미 설정이 있으면 내용을 보관하고 필요한 항목만 수정합니다.
프로젝트 설정은 신뢰된 프로젝트에서 로드되며 관리 정책의 제한을 받습니다.

---

## 단계 3. 읽기 전용 환경에서 조사

VS Code 편집기로 프로젝트 설정을 작성합니다.

```toml
approval_policy = "on-request"
sandbox_mode = "read-only"
```

확장을 재시작하고 새 채팅에서 아래 요청을 보냅니다.

```text
상품 조회의 실행 경로를 조사해줘. 파일은 수정하지 마.
```

실제로 조사에 필요한 읽기 작업이 가능한지 확인합니다.

---

## 단계 4. 쓰기 요청과 권한 비교

```text
docs/lab-notes/settings-probe.txt에 'settings probe'를 저장해줘.
권한 때문에 쓸 수 없다면 필요한 권한과 이유를 알려줘.
다른 위치로 우회해서 저장하지 마.
```

읽기 전용이면 쓰기가 제한되거나 승인 요청이 나타날 수 있습니다.
관리 정책·클라이언트에 따라 실제 메시지가 달라질 수 있습니다.
설정 변경 전후의 메시지와 생성 여부를 기록합니다.

---

## 단계 5. 개발용 설정으로 복귀

편집기로 다음 설정을 적용하고 확장을 재시작합니다.

```toml
approval_policy = "on-request"
sandbox_mode = "workspace-write"
```

같은 파일 생성 요청을 다시 실행합니다.
여전히 제한된다면 작업 루트·신뢰 상태·관리 정책을 확인합니다.
설정 파일이 있다고 실제 권한이 무조건 적용된 것은 아닙니다.

---

## 추론 수준은 작업에 맞춰 비교

현재 모델과 클라이언트가 제공하는 수준을 UI에서 확인합니다.

- 단순 문구 수정 계획과 DB 전환 계획을 각각 요청합니다.
- 가능하면 서로 다른 수준에서 변경 범위·질문·검증 계획을 비교합니다.
- 속도 한 번만으로 품질의 우열을 결론 내리지 않습니다.

지원하는 경우 `model_reasoning_effort`로 기본값을 설정할 수 있습니다.
모든 모델이 같은 수준을 지원한다고 가정하지 않습니다.

---

## 단계 6. 서비스의 Groq 설정 준비

`.env`에서 다음 두 값을 직접 작성합니다.

```dotenv
GROQ_API_KEY=본인의_키
GROQ_MODEL=계정에서_사용_가능한_모델_ID
```

위 문자열은 예시 자리표시자입니다. 그대로 실행하지 않습니다.
키를 채팅에 붙이지 않고 [Groq 모델 목록](https://console.groq.com/docs/models)에서
모델과 계정 사용 가능 여부를 확인합니다.

---

## 단계 7. 고정 응답과 실제 호출 비교

```powershell
uv run --locked python -m scripts.check_llm
uv run --locked python -m scripts.check_llm --live
```

첫 명령은 외부 호출 없는 고정 응답입니다.
두 번째는 연결 테스트 문장으로 Groq를 실제 호출합니다.

성공 응답·모델 ID·확인 시각만 기록하고 키는 기록하지 않습니다.
실패 시 계정·모델·네트워크를 확인하고 `미완료`로 기록합니다.

---

## 단계 8. 설정을 혼동하지 않는지 점검

```text
이번에 변경한 AGENTS.md, .codex/config.toml, .env의 역할을
비밀값 없이 설명해줘. 실제 Groq 호출 실패를 stub 성공으로
바꿔 보고하지 않는지 integrations/llm.py도 확인해줘.
수정이 필요하면 먼저 변경 이유를 설명해줘.
```

실제 상담은 9장에서 연결합니다. 상품 조회에는 API 키가 필요 없습니다.
