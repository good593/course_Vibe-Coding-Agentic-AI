# 웹 개발자를 위한 Codex 에이전틱 개발 실전

> **Codex에게 코드를 시키는 법이 아니라, 계획·규칙·검증 기준이 포함된 개발 업무를 맡기는 법을 배운다.**

## 과정 개요

- 대상: 웹 개발 입문자
- 환경: Windows, Codex 데스크톱 앱, PowerShell
- 기술: React + Vite / FastAPI
- 프로젝트: 팀 프로젝트 운영 대시보드
- 권장 구성: 11차시 × 차시당 2시간
- 최종 결과: 테스트와 Git 이력이 포함된 팀 프로젝트 수준의 풀스택 대시보드

Codex Windows 앱은 PowerShell과 Windows 샌드박스를 지원하므로 Windows 중심 과정으로 구성할 수 있습니다. [Windows용 Codex 공식 문서](https://learn.chatgpt.com/docs/windows/windows-app)

## Work 과정과의 차별점

| ChatGPT Work 과정 | Codex 과정 |
|---|---|
| 대화로 결과물 생성 | 저장소 안에서 실제 코드 변경 |
| 문서·이미지·사이트 제작 | 프론트엔드·백엔드 기능 구현 |
| 결과물 확인 중심 | diff·테스트·실행 결과 검증 |
| 개인 업무 자동화 | 개발 규칙과 반복 작업 자동화 |
| 완성된 결과물 중심 | 브랜치·커밋·PR까지 과정 관리 |
| “무엇을 만들어줘” | “이 기준으로 계획하고 구현하고 검증해줘” |

## 공통 실습 프로젝트

### TeamFlow Dashboard

팀의 프로젝트 진행 상황을 관리하는 풀스택 대시보드입니다.

주요 기능은 다음과 같습니다.

- 프로젝트 현황 KPI 카드
- 프로젝트 목록과 진행 상태
- 담당자·상태별 필터
- 업무 생성 및 상태 변경
- FastAPI 서버에서 데이터 조회
- 로딩·오류·빈 화면 처리
- 프론트엔드와 백엔드 테스트
- 기능별 Git 브랜치와 Pull Request
- Codex를 통한 코드 리뷰

모든 차시에서 같은 프로젝트를 조금씩 발전시킵니다.

## 1차시. Codex에게 개발 업무 맡기기

### 학습 목표

- 일반 챗봇과 코딩 에이전트의 차이를 이해한다.
- Codex 앱에서 프로젝트 폴더를 연다.
- Codex가 파일과 터미널을 사용하는 과정을 확인한다.
- 권한 요청을 승인하기 전에 무엇을 봐야 하는지 이해한다.

### 실습

- Windows 개발 환경 확인
- React/FastAPI 스타터 프로젝트 열기
- 프로젝트 구조를 Codex에게 설명하게 하기
- 작은 문구 수정 요청
- 변경된 파일과 diff 직접 확인

### 결과물

- 실행 가능한 스타터 프로젝트
- 첫 번째 변경사항
- Codex 작업 확인 체크리스트

## 2차시. 코드보다 먼저 프로젝트 이해시키기

### 학습 목표

- 모호한 요구를 바로 구현시키지 않는 습관을 익힌다.
- 기존 코드베이스를 조사하게 한다.
- 요구사항과 완료 조건을 구분한다.

### 실습

Codex에게 다음 순서로 업무를 맡깁니다.

1. 프로젝트 구조 조사
2. 프론트엔드와 백엔드 실행 방법 확인
3. 주요 데이터 흐름 설명
4. 구현 전에 확인할 질문 작성
5. 기능의 완료 조건 정의

### 결과물

- `docs/project-overview.md`
- `docs/requirements.md`
- 기능별 완료 조건 체크리스트

## 3차시. `AGENTS.md`로 프로젝트 규칙 만들기

### 학습 목표

- 반복해서 설명할 개발 규칙을 파일로 관리한다.
- 프론트엔드와 백엔드의 작업 규칙을 구분한다.
- 코딩 스타일뿐 아니라 실행·검증 규칙까지 정의한다.

### 실습

`AGENTS.md`에 다음 내용을 정의합니다.

- 프로젝트 구조
- React와 FastAPI 실행 명령
- 파일과 컴포넌트 명명 규칙
- API 응답 형식
- 수정 금지 영역
- 작업 완료 전 실행해야 할 테스트
- Git 커밋 규칙
- 결과 보고 형식

### 결과물

- 프로젝트 루트 `AGENTS.md`
- 필요하면 frontend/backend 하위 규칙 파일

`AGENTS.md`는 Codex에 프로젝트별 지침을 제공하는 공식 구성 방식입니다. [AGENTS.md 공식 문서](https://learn.chatgpt.com/docs/agent-configuration/agents-md)

## 4차시. Plan으로 구현 전에 설계하기

### 학습 목표

- 계획이 필요한 작업과 바로 수정해도 되는 작업을 구분한다.
- 큰 요청을 검증 가능한 작업으로 나눈다.
- 잘못된 계획을 구현 전에 수정한다.

### 실습

“프로젝트 상태 필터 기능”을 바로 구현하지 않고 다음 과정을 거칩니다.

1. 관련 파일 조사
2. 현재 구조 설명
3. 구현 계획 작성
4. 변경 예상 파일 확인
5. 테스트 계획 확인
6. 계획에 피드백
7. 승인한 계획만 구현

### 결과물

- `docs/feature-plan.md`
- 기능 작업 체크리스트
- 계획 검토용 질문 목록

### 핵심 메시지

> 좋은 프롬프트보다 좋은 작업 계획과 완료 조건이 중요하다.

## 5차시. Codex와 React 대시보드 UI 구현하기

### 학습 목표

- 화면 요구사항을 컴포넌트 단위로 나눈다.
- Codex가 만든 UI를 실행 화면과 코드 양쪽에서 검토한다.
- 한 번에 전체 화면을 맡기지 않고 단계별로 완성한다.

### 실습

- 대시보드 레이아웃 구현
- KPI 카드
- 프로젝트 테이블
- 상태 배지
- 필터 UI
- 반응형 화면
- 로딩·빈 화면·오류 화면

### 결과물

- React + Vite 대시보드
- 재사용 가능한 UI 컴포넌트
- 임시 데이터 기반 화면

### Work 사이트 제작과의 차이

Work 과정이 대화에서 사이트 결과물을 빠르게 만드는 데 초점을 둔다면, Codex 과정에서는 실제 React 소스 코드, 컴포넌트 구조, 실행 환경과 변경 이력을 함께 관리합니다.

## 6차시. FastAPI 백엔드 개발 맡기기

### 학습 목표

- 프론트엔드 요구사항을 API 계약으로 변환한다.
- Codex에게 백엔드 기능을 작은 단위로 맡긴다.
- 생성된 코드를 실행하고 API 응답을 확인한다.

### 실습

- FastAPI 프로젝트 구조 확인
- Pydantic 모델 작성
- 프로젝트 목록 API
- 프로젝트 생성 API
- 상태 변경 API
- 입력값 검증과 오류 응답
- Swagger UI에서 API 확인

### 결과물

- 실행 가능한 FastAPI 서버
- 프로젝트 CRUD API
- API 명세

## 7차시. 프론트엔드와 백엔드 연결하기

### 학습 목표

- 전체 데이터 흐름을 계획한 뒤 연동한다.
- 정상 상황뿐 아니라 실패 상황도 구현한다.
- 기능 완료 여부를 사용자 관점에서 검증한다.

### 실습

- React에서 FastAPI 호출
- 환경 변수 설정
- CORS 문제 진단
- 로딩과 오류 처리
- 필터 조건을 API에 전달
- 데이터 생성 후 화면 갱신

### 결과물

- 실제 API와 연결된 대시보드
- 통합 기능 검증 체크리스트

## 8차시. 테스트 작성과 실행 맡기기

### 학습 목표

- “잘 작동한다”는 말 대신 테스트 결과를 요구한다.
- 구현 코드와 테스트 코드를 함께 검토한다.
- 실패하는 테스트로 버그를 재현한 뒤 수정한다.

### 실습

- 테스트 대상과 테스트하지 않을 대상 구분
- Vitest 기반 프론트엔드 테스트
- pytest 기반 FastAPI 테스트
- 의도적으로 버그 만들기
- 실패 테스트 작성
- 최소 수정으로 버그 해결
- 전체 테스트 다시 실행

### 결과물

- 프론트엔드 단위 테스트
- 백엔드 API 테스트
- 테스트 실행 결과
- 버그 재현 및 수정 기록

## 9차시. Git 브랜치·커밋·PR로 협업하기

### 학습 목표

- 하나의 기능을 하나의 브랜치에서 관리한다.
- 커밋하기 전에 Codex의 변경을 직접 검토한다.
- PR 설명과 리뷰 의견을 작성하게 한다.

### 실습

- 기능 브랜치 생성
- `git status`와 `git diff` 확인
- 변경사항을 논리적인 커밋으로 나누기
- 커밋 메시지 생성 및 검토
- PR 설명 작성
- Codex 코드 리뷰
- 리뷰 결과를 심각도별로 분류
- 필요한 항목만 수정

### 결과물

- 기능 브랜치
- 의미 있는 Git 커밋
- Pull Request
- 코드 리뷰 보고서

Codex 공식 문서도 코드 리뷰를 별도의 개발 워크플로로 다루고 있습니다. [Codex 코드 리뷰 공식 문서](https://learn.chatgpt.com/docs/code-review)

## 10차시. 우리 팀의 Codex 스킬 만들기

### 학습 목표

- Work용 콘텐츠 제작 스킬과 개발용 Codex 스킬의 차이를 이해한다.
- 반복되는 개발 절차를 재사용 가능한 스킬로 만든다.
- 스킬이 언제 실행되고 무엇을 검증해야 하는지 정의한다.

### 실습

`feature-delivery` 스킬을 만듭니다.

이 스킬은 다음 절차를 수행합니다.

1. 요구사항 분석
2. 관련 코드 조사
3. 구현 계획 작성
4. 승인된 범위 구현
5. 테스트 실행
6. diff 검토
7. PR 설명 초안 작성
8. 변경사항과 위험 요소 보고

### 결과물

- `SKILL.md`
- 스킬 실행 체크리스트
- 대시보드 기능을 이용한 실행 사례

Codex의 스킬은 반복되는 개발 작업 절차와 지원 파일을 패키지화하는 데 사용할 수 있습니다. [Codex 스킬 공식 문서](https://learn.chatgpt.com/docs/build-skills)

## 11차시. 팀 프로젝트 기능 개발과 최종 리뷰

### 학습 목표

- 처음부터 끝까지 하나의 개발 업무를 Codex에 맡긴다.
- 팀원이 만든 변경을 통합하고 검증한다.
- 결과가 아니라 개발 과정 전체를 평가한다.

### 팀별 기능 예시

- 대시보드 검색 기능
- 프로젝트 상세 화면
- 업무 담당자 변경
- 마감일 경고
- 차트 시각화
- 다크 모드
- 활동 로그

### 최종 수행 과정

1. 요구사항 작성
2. 이슈 생성
3. 브랜치 생성
4. Plan 검토
5. 기능 구현
6. 테스트 작성
7. diff 검토
8. 커밋
9. PR 생성
10. 코드 리뷰와 수정
11. 최종 실행 및 발표

### 최종 결과물

- 테스트 코드와 실행 결과
- 기능 브랜치와 커밋
- PR과 코드 리뷰 기록
- 팀 전용 Codex 스킬
- 프로젝트 README
