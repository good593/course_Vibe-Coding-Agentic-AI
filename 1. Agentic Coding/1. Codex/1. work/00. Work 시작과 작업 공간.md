# ChatGPT Work 시작과 작업 공간

Chat·Work·Projects·Chats를 목적에 맞게 선택하기

---

## 오늘의 목표

- Chat과 Work의 역할을 구분한다.
- Project와 Chat을 목적에 맞게 구성한다.
- 웹·데스크톱, 로컬·클라우드 실행 차이를 확인한다.
- Work 결과물을 검토하는 기본 절차를 익힌다.

---

## Chat과 Work

| 구분 | Chat | Work |
|---|---|---|
| 적합한 요청 | 질문, 아이디어, 짧은 초안 | 여러 단계의 실질적 업무 |
| 입력 | 대화 중심 | 파일·도구·여러 출처 |
| 결과 | 답변 | 검토·재사용 가능한 산출물 |
| 진행 | 짧은 상호작용 | 계획·진행·수정·승인 |

핵심 질문은 “답이 필요한가, 완료된 결과물이 필요한가?”다.

---

## 좋은 Work 과제

- 결과물이 명확하다.
- 사용할 원자료가 있다.
- 여러 단계 또는 도구가 필요하다.
- 사람이 검토할 기준이 있다.
- 중간에 질문하거나 방향을 바꿀 수 있다.

예: “시장에 대해 알려줘”보다 “세 출처를 비교해 의사결정 메모와 근거표를 만들어줘”가 적합하다.

---

## Project와 Chat

- Project: 관련 자료·지침·Chat을 묶는 작업 공간
- Chat: 하나의 구체적인 완료 목표

권장 구조:

```text
동네 클래스 예약 서비스
├─ 사용자 조사 Chat
├─ 경쟁사 조사 Chat
├─ PRD 작성 Chat
└─ 주간 업데이트 Chat
```

---

## Project를 만들 때

포함할 것:

- 제품 한 줄 설명
- 대상 사용자와 의사결정 목적
- 승인된 공통 자료
- 출력 언어·형식·검증 원칙

넣지 않을 것:

- 실제 개인정보와 회사 비밀
- 관련 없는 대용량 자료
- 최신 여부를 확인할 수 없는 파일

---

## 웹과 데스크톱

| 표면 | 강점 |
|---|---|
| Web | 클라우드 Work, 파일 업로드, 연결 도구, 어디서나 접근 |
| Desktop | 로컬 파일·앱·브라우저, Appshot, 한 화면의 결과 검토 |

기능 제공 범위는 계정·운영체제·조직 정책에 따라 다를 수 있다.

---

## 로컬과 클라우드

- Local: 컴퓨터의 파일·앱을 사용해야 할 때
- Cloud: 컴퓨터가 꺼져도 이어질 수 있는 장기·예약 작업

확인할 것:

- 자료가 실제로 어디에 있는가?
- 어느 환경으로 업로드 또는 전달되는가?
- 작업 중 컴퓨터를 켜두어야 하는가?
- 조직 정책이 허용하는가?

---

## 강사 시연

같은 원자료로 두 요청을 비교한다.

Chat:

> 이 인터뷰를 세 줄로 요약해줘.

Work:

> 인터뷰 5개를 분석해 문제 패턴·근거 인용·우선순위·미확인 질문이 포함된 의사결정 메모를 만들어줘.

---

## 실습

1. `동네 클래스 예약 서비스` Project를 만든다.
2. 제품 소개와 샘플 인터뷰를 Sources에 추가한다.
3. Chat과 Work에 동일한 요약 요청을 실행한다.
4. 산출물의 구조·근거·수정 가능성을 비교한다.
5. 다음 작업을 별도 Chat으로 분리한다.

---

## 제출물

- Project 구조 캡처
- Chat과 Work 결과 비교표
- Work가 실제로 사용한 원자료 목록
- 웹·데스크톱 기능 차이 기록
- 검토 없이 사용할 수 없는 항목

---

## 완료 체크

- [ ] 질문과 업무 위임을 구분할 수 있다.
- [ ] 하나의 Chat에 하나의 완료 목표를 두었다.
- [ ] Project의 공통 자료와 지침을 확인했다.
- [ ] 실행 환경과 데이터 위치를 설명할 수 있다.
- [ ] 결과의 근거와 미확인 사항을 검토했다.
