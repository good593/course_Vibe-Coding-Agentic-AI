# 멀티모달 컨텍스트

파일·폴더·이미지·Appshot·음성을 신뢰 가능한 입력으로 만들기

---

## 오늘의 목표

- 과제에 필요한 입력만 선별한다.
- 파일과 폴더의 범위·최신성·출처를 확인한다.
- 이미지·Appshot·음성을 구조화된 정보로 변환한다.
- 충돌하는 자료와 미확인 사실을 분리한다.

---

## 컨텍스트가 많으면 항상 좋을까?

과도한 컨텍스트의 문제:

- 오래된 자료가 최신 자료를 덮는다.
- 서로 다른 제품·기간의 정보가 섞인다.
- 개인정보와 비밀자료가 불필요하게 노출된다.
- 무엇을 근거로 했는지 추적하기 어려워진다.

필요한 최소 자료와 명시적인 출처 목록이 더 중요하다.

---

## 입력 자료 명세

| 파일 | 용도 | 기준일 | 신뢰 수준 | 제외 항목 |
|---|---|---|---|---|
| product-brief.pdf | 제품 범위 | 2026-08-20 | 승인본 | 예산 추정 |
| interviews.docx | 사용자 문제 | 2026-08 | 원문 | 이름·연락처 |
| survey.csv | 선호도 분석 | 2026-08-25 | 원본 export | 자유응답 PII |
| screen.png | 현재 UX | 2026-08-28 | 실제 화면 | 테스트 계정 정보 |

---

## 파일과 폴더

- 개별 파일: 범위가 명확한 일회성 입력
- 폴더: 여러 파일의 지속적 탐색이 필요한 로컬 Work
- Project Sources: 여러 Chat이 공유할 승인된 자료

요청 후 Work가 실제로 읽은 파일과 읽지 못한 파일을 보고하게 한다.

---

## 이미지 입력

이미지로 확인하기 좋은 것:

- 레이아웃과 정보 계층
- 사용자에게 보이는 오류
- 문서의 표·차트
- 물리적 메모와 화이트보드

이미지에서 추론한 정보는 원본 데이터나 텍스트로 다시 확인한다.

---

## Appshot

Appshot은 데스크톱 앱에서 다른 앱의 화면을 현재 작업 컨텍스트로 전달할 때 유용하다.

확인할 것:

- 어떤 앱과 화면이 캡처되는가?
- 알림·계정명·고객정보가 보이지 않는가?
- 전체 화면 대신 필요한 영역만 제공할 수 있는가?
- 화면 관찰과 실제 데이터가 일치하는가?

---

## 음성 입력

회의 음성을 바로 결정사항으로 취급하지 않는다.

변환 순서:

1. 발언 또는 메모 전사
2. 결정·가설·질문·실행 항목 분리
3. 담당자와 기한 확인
4. 원문과 표본 대조
5. 참석자 검토가 필요한 항목 표시

---

## 충돌하는 자료

요청 예:

```text
자료를 합치기 전에 출처별 핵심 사실을 표로 정리해줘.
수치·날짜·요구사항이 충돌하면 임의로 선택하지 말고
양쪽 근거와 확인이 필요한 질문을 표시해줘.
```

최신 파일이라는 이유만으로 항상 더 정확한 것은 아니다.

---

## 강사 시연

제품 브리프·회의 음성·화면 캡처·설문 CSV를 추가한다.

- 입력 자료 명세 작성
- 개인정보 제거
- Work가 읽은 범위 확인
- 회의록 구조화
- 화면 문제와 설문 근거 연결
- 충돌 사항 표 생성

---

## 실습

1. 제공 자료에서 사용할 파일을 선택한다.
2. 입력 자료 명세를 작성한다.
3. Appshot 또는 샘플 화면 이미지로 UX 문제를 설명한다.
4. 회의 음성을 결정·가설·질문으로 변환한다.
5. 서로 충돌하는 요구사항을 찾아 확인 질문을 만든다.

대체 실습: Appshot·음성을 사용할 수 없으면 제공된 이미지·전사 파일로 동일한 검증 절차를 수행한다.

---

## 제출물

- 입력 자료 명세
- 제거하거나 마스킹한 정보 목록
- 화면 관찰 결과
- 구조화된 회의록
- 자료 충돌과 확인 질문 표
