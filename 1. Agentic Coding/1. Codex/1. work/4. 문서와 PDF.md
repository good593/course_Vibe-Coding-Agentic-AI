# 문서와 PDF

근거가 추적되고 수정 가능한 PRD 만들기

---

## 오늘의 목표

- 문서의 독자·구조·검토 기준을 먼저 정의한다.
- 여러 자료에서 근거를 추출해 PRD를 만든다.
- 미리보기와 주석으로 특정 부분을 수정한다.
- PDF 내보내기 후 내용과 레이아웃을 재검증한다.

---

## 문서 작업 브리핑

```text
산출물: 3쪽 이내 MVP PRD
독자: 제품·디자인·개발·운영
근거: 승인된 인터뷰와 조사 근거표만 사용
필수 절: 문제, 사용자, 범위, 비범위, 흐름, 지표, 위험
검토: 모든 수치와 주요 주장에 출처 표시
제외: 구현 기술 확정, 확인되지 않은 시장 수치
```

---

## PRD의 최소 구조

1. 배경과 문제
2. 대상 사용자와 상황
3. 목표와 성공 지표
4. 범위와 비범위
5. 핵심 사용자 흐름
6. 기능 요구사항과 예외
7. 정책·운영·데이터 위험
8. 미결정 사항과 다음 검증

형식보다 의사결정과 근거의 연결이 중요하다.

---

## 근거 연결

| 요구사항 | 근거 | 확실성 | 반대 근거 | 확인 방법 |
|---|---|---|---|---|
| 당일 취소 제한 | 운영 인터뷰 2·4 | 중간 | 사용자 불편 | 정책 테스트 |

Work가 원자료에 없는 내용을 채우면 “가정”으로 표시한다.

---

## 기존 문서 수정

전체 재작성보다 특정 범위 수정이 안전하다.

```text
성공 지표 절만 수정해줘.
기존 문체와 번호 체계를 유지하고,
변경한 문장·변경 이유·근거 출처를 표로 함께 보여줘.
다른 절은 수정하지 마.
```

변경 전후 의미가 달라지지 않았는지 확인한다.

---

## 미리보기와 주석

- 문서 전체 구조 확인
- 특정 문단이나 표를 선택해 수정 요청
- 누락된 제목·페이지 나눔·표 깨짐 확인
- 원본 파일과 수정본을 구분해 저장

“더 좋게”보다 수정 위치와 기준을 지정한다.

---

## PDF 읽기

PDF에서 확인할 것:

- 텍스트로 읽히는가, 스캔 이미지인가?
- 표와 각주가 올바른 순서로 해석되는가?
- 페이지 번호와 인용 위치가 정확한가?
- 그래프 축·단위·범례를 놓치지 않았는가?

핵심 수치와 인용은 원 페이지를 직접 확인한다.

---

## PDF 내보내기 검증

1. 생성한 문서를 PDF로 내보낸다.
2. PDF를 새 입력으로 다시 연다.
3. 제목·표·페이지·링크·특수문자를 확인한다.
4. 원 문서와 핵심 수치·요구사항을 대조한다.
5. 수정 가능한 원본과 배포 PDF를 함께 보관한다.

---

## 강사 시연

- 조사 근거표에서 PRD 초안 생성
- 미확인 주장을 별도 표시
- 미리보기 주석으로 요구사항 표 수정
- PDF 내보내기
- PDF 역검증과 누락 수정

---

## 실습

`03-artifacts` 자료 팩으로 MVP PRD를 만든다.

- 승인된 자료만 사용
- 요구사항 5개 이상과 예외 조건
- 범위·비범위 명시
- 근거와 가정 구분
- 주석을 이용한 특정 수정 2회
- PDF 내보내기 후 재검증

---

## 제출물

- 최종 PDF

- 변경 전후 검토 기록
- PDF에서 발견한 오류와 수정 내용
