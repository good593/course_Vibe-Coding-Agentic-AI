# 스프레드시트와 시각화

설문 데이터를 검산 가능한 의사결정 자료로 만들기

---

## 오늘의 목표

- 원본 데이터를 보존하며 정리한다.
- 지표 정의와 계산식을 명시한다.
- 표본 검산으로 수식과 분류를 검증한다.
- 차트·Visualization의 표현과 왜곡 가능성을 평가한다.

---

## 분석 시작 전 데이터 계약

| 항목 | 예시 |
|---|---|
| 분석 단위 | 응답자 1명당 1행 |
| 고유 키 | response_id |
| 기준 기간 | 2026-08-01~31 |
| 결측값 | 빈 문자열은 미응답 |
| 중복 처리 | 최신 submitted_at 유지 |
| 제외 기준 | 테스트 계정, 동의 철회 |

정의되지 않은 데이터를 Work가 임의로 보정하지 않게 한다.

---

## 원본 보존

- 원본 sheet는 수정하지 않는다.
- 정리본과 계산 sheet를 분리한다.
- 변경한 열과 제외한 행의 이유를 기록한다.
- 데이터 최신 시각을 표시한다.
- 개인정보 열은 제거하거나 익명화한다.

분석 결과보다 재현 가능한 데이터 흐름이 먼저다.

---

## 우선순위 점수 예시

```text
Priority = Reach × Impact × Confidence ÷ Effort
```

반드시 정의할 것:

- 각 변수의 단위와 범위
- Confidence의 근거
- 결측값 처리
- 동점 처리
- 점수가 의사결정을 자동 확정하지 않는다는 점

---

## 표본 검산

전체 결과를 믿기 전에 3~5행을 직접 계산한다.

1. 원본 값 확인
2. 정리 규칙 적용
3. 수식 수동 계산
4. Work 결과와 비교
5. 차이가 있으면 전체 분석 중단 후 원인 확인

합계·평균·비율의 분모도 함께 검토한다.

---

## 차트 선택

| 질문 | 적합한 표현 |
|---|---|
| 범주 비교 | 막대 차트 |
| 시간 변화 | 선 차트 |
| 구성 비율 | 누적 막대·제한적 원형 |
| 두 변수 관계 | 산점도 |
| 단계별 이탈 | 퍼널 또는 단계 표 |

3D 효과와 잘린 축은 차이를 과장할 수 있다.

---

## Visualization 검토

- 제목이 질문을 정확히 표현하는가?
- 단위·범례·기간·분모가 보이는가?
- 필터가 실제 데이터에 적용되는가?
- 정렬과 색상이 오해를 만들지 않는가?
- 원자료와 계산 과정으로 돌아갈 수 있는가?

상호작용이 많다고 분석이 더 정확한 것은 아니다.

---

## 분석 프롬프트 예시

```text
원본 sheet는 변경하지 말고 정리본과 계산 sheet를 분리해줘.
중복·결측·제외 행을 별도 표로 남기고,
우선순위 점수의 변수·수식·가정을 명시해줘.
차트 생성 전 표본 5행을 검산하고 결과를 보고해줘.
```

---

## 강사 시연

- 설문 CSV 구조 확인
- 중복·결측 처리 계획 승인
- 정리본과 계산 sheet 생성
- 우선순위 점수 표본 검산
- 차트와 Visualization 생성
- 같은 데이터를 왜곡하는 표현 비교

---

## 실습

설문과 기능 후보 데이터를 분석한다.

- 데이터 계약 작성
- 원본·정리·계산 sheet 분리
- 우선순위 수식과 가정 기록
- 표본 5행 검산
- 차트 2개와 Visualization 1개
- 의사결정 2개와 반대 근거 작성
