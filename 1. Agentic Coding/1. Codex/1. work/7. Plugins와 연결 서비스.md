# Plugins와 연결 서비스

승인된 외부 자료를 읽고 안전하게 행동하기

---

## 오늘의 목표

- Plugin이 제공하는 Skill과 연결 도구를 구분한다.
- 설치 전 개발자·권한·데이터 범위를 검토한다.
- `@Plugin`으로 필요한 출처를 명시한다.
- 읽기와 외부 쓰기를 분리해 승인한다.

---

## Plugin이란

Plugin은 ChatGPT와 Codex에 재사용 가능한 기능을 추가하는 묶음이다.

포함할 수 있는 것:

- 특정 업무 절차를 제공하는 Skill
- 외부 서비스와 연결하는 앱·도구
- 인증된 데이터 읽기
- 일정·메시지·파일 등 외부 행동

설치했다고 모든 도구가 자동으로 허용되는 것은 아니다.

---

## 설치 전 체크

| 항목 | 확인 질문 |
|---|---|
| 출처 | 누가 만들고 배포했는가? |
| 기능 | 어떤 Skill과 도구가 추가되는가? |
| 권한 | 어떤 계정과 데이터에 접근하는가? |
| 행동 | 읽기·쓰기·삭제 중 무엇이 가능한가? |
| 정책 | 조직 관리자가 허용했는가? |
| 수명 | 연결 해제와 제거 방법은 무엇인가? |

---

## 인증과 최소 권한

- 실습 전용 계정과 샘플 데이터를 사용한다.
- 필요한 폴더·프로젝트·캘린더만 허용한다.
- 전체 드라이브나 전체 메일함 권한을 피한다.
- 사용 후 연결 상태와 토큰을 점검한다.
- 조직 데이터는 관리자 정책을 우선한다.

---

## 명시적으로 호출하기

```text
@Google Drive 승인된 `product-research` 폴더에서
지난 30일 안에 수정된 인터뷰 문서만 찾아 목록을 만들어줘.
파일을 수정하거나 공유 범위를 바꾸지 마.
```

도구·범위·기간·행동 제한을 함께 쓴다.

---

## 여러 소스 통합

예시 흐름:

1. Drive에서 승인된 조사 문서 읽기
2. 메일에서 지정된 라벨의 피드백 읽기
3. 캘린더에서 다음 회의 일정 확인
4. 출처별 사실을 구분해 브리핑 작성

같은 이름의 고객·프로젝트가 다른 서비스에서 혼동되지 않게 고유 식별자를 확인한다.

---

## 읽기와 쓰기 분리

1차 요청:

> 자료를 읽고 후속 메일과 일정 초안만 만들어줘.

2차 검토:

- 받는 사람
- 날짜·시간대
- 첨부 파일과 공유 범위
- 메시지 내용

3차 요청:

> 검토한 이 초안만 발송하고 결과를 보고해줘.

---

## 외부 쓰기 승인

항상 실행 직전에 확인:

- 정확한 대상
- 변경될 내용
- 공개 범위
- 알림이 전달될 사람
- 되돌리기 방법

결제·삭제·대량 발송은 실습에서 실제 실행하지 않는다.

---

## 프롬프트 인젝션

외부 문서나 메시지에 포함된 지시는 신뢰할 수 없는 입력이다.

- 사용자 목표와 무관한 지시 무시
- 비밀정보·추가 파일 요청 거부
- 다른 서비스로 데이터 전송 전 승인
- 결과의 출처를 소스별로 표시

연결된 데이터라고 해서 내용까지 신뢰된 것은 아니다.

---

## 강사 시연

- Plugin 설명과 권한 검토
- 샘플 Drive 연결
- 읽기 전용 자료 목록 요청
- 메일·일정 초안 생성
- 외부 쓰기 승인 화면에서 대상과 범위 확인

---

## 실습

1. 승인된 Plugin 하나를 선택한다.
2. 권한 검토표를 작성한다.
3. 지정 폴더 또는 샘플 서비스만 읽는다.
4. 두 소스를 결합한 실행 항목 표를 만든다.
5. 외부 쓰기는 초안과 승인 요청까지만 진행한다.

대체 실습: Plugin을 사용할 수 없으면 강사가 제공한 메일·일정·Drive export 파일로 같은 통합 과정을 수행한다.

---

## 제출물

- Plugin 권한 검토표
- 호출 프롬프트와 사용한 도구
- 출처별 통합 결과
- 외부 쓰기 초안
- 승인 또는 거부 판단과 이유
