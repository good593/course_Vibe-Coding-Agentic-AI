# Sites

문서와 데이터를 상호작용 가능한 기획 결과물로 만들기

---

## 오늘의 목표

- Site가 적합한 결과물과 문서·덱의 차이를 구분한다.
- 데이터와 출처가 연결된 내부 대시보드를 만든다.
- 필터·상태·모바일 화면을 검토한다.
- 공유 전 데이터 최신성과 접근 범위를 확인한다.

---

## 언제 Site를 쓰는가

Site가 잘 맞는 경우:

- 여러 사람이 반복해서 보는 현황판
- 필터와 탐색이 필요한 데이터
- 문서·표·차트를 한 화면에 연결
- 간단한 내부 도구나 프로토타입

한 번 읽고 결정하는 보고라면 문서나 발표자료가 더 단순할 수 있다.

---

## 제품 현황 Site 구조

```text
요약 KPI
├─ 사용자 문제와 최신 인사이트
├─ 기능 우선순위 표
├─ 일정과 위험
├─ 실험 결과 차트
└─ 원자료·정의·최근 업데이트
```

첫 화면에서 독자와 결정 목적을 알 수 있어야 한다.

---

## 데이터 연결 원칙

- 원자료 위치와 마지막 갱신 시각 표시
- 계산 지표의 정의와 분모 공개
- 샘플·실제 데이터를 명확히 구분
- 누락·불일치 레코드 별도 표시
- 연결이 끊겼을 때 오래된 데이터를 최신처럼 보이지 않기

Site는 데이터를 스스로 갱신하는 작업이 아니다. 필요한 경우 Scheduled task가 별도로 갱신한다.

---

## 상호작용 설계

필터 예:

- 기간
- 사용자 유형
- 클래스 카테고리
- 지역

확인할 것:

- 필터를 바꾸면 KPI와 차트가 함께 바뀌는가?
- 초기화 방법이 있는가?
- 빈 결과와 오류 상태가 보이는가?
- 선택한 필터가 화면에 표시되는가?

---

## 공유 전 검토

| 항목 | 질문 |
|---|---|
| 독자 | 누가 볼 수 있어야 하는가? |
| 데이터 | 개인정보·민감정보가 있는가? |
| 최신성 | 언제 갱신되었는가? |
| 출처 | 원자료로 돌아갈 수 있는가? |
| 접근 | 링크를 가진 모두인가, 지정 사용자만인가? |
| 상태 | 모바일·빈 값·오류를 확인했는가? |

---

## 프롬프트 예시

```text
PRD와 검산된 우선순위 스프레드시트를 사용해
내부 제품 현황 Site를 만들어줘.

포함: KPI 3개, 우선순위 표, 위험, 일정, 출처
상호작용: 기간·카테고리 필터
표시: 샘플 데이터 배지와 최근 업데이트 시각
공유: 게시하거나 권한을 변경하지 말고 미리보기만 생성
```

---

## 강사 시연

- 문서·스프레드시트 연결
- Site 초안 생성
- KPI 정의와 출처 확인
- 필터·빈 상태·모바일 확인
- 공유 범위 검토
- Scheduled task와 Site 갱신의 차이 설명

---

## 실습

제품 우선순위 대시보드를 만든다.

- KPI 3개
- 필터 2개 이상
- 기능 우선순위 표와 차트
- 최신 시각·출처·샘플 데이터 표시
- 모바일과 빈 상태 검토
- 공유 전 체크리스트 작성

대체 실습: Sites를 사용할 수 없으면 상호작용 요구사항과 화면 구조를 문서 프로토타입으로 작성한다.

---

## 제출물

- Site 미리보기 또는 대체 프로토타입
- 데이터·지표 정의서
- 필터 테스트 결과
- 모바일·빈 상태 화면
- 공유 승인 체크리스트
