# Skills·Plugins·MCP·WebMCP

반복 절차를 재사용하고 외부 도구를 안전하게 연결하기

---

## 오늘의 목표

- Skill·Plugin·MCP의 역할을 구분한다.
- 반복 가능한 검증 Skill을 설계한다.
- MCP 서버를 연결하고 도구 범위를 확인한다.
- 외부 도구의 인증·쓰기·프롬프트 인젝션 위험을 평가한다.

---

## 어떤 확장 방식을 쓸까

| 방식 | 해결하는 문제 | 예시 |
|---|---|---|
| `AGENTS.md` | 저장소의 지속 규칙 | 테스트·스타일·완료 조건 |
| Skill | 반복 가능한 작업 절차 | PR 검증, 릴리스 체크 |
| Plugin | 배포 가능한 기능 묶음 | Skill + MCP + Hook + 자산 |
| MCP | 외부 데이터와 행동 도구 | 이슈·DB·문서 조회 |
| WebMCP | 사이트가 제공하는 브라우저 도구 | 페이지 안의 구조화된 작업 |

---

## 좋은 Skill의 조건

- 하나의 명확한 목적
- 구체적인 사용 조건
- 입력·출력·중단 조건
- 필요한 참조만 단계적으로 읽기
- 스크립트 결과를 검증하는 절차
- 실패 시 안전한 대안

Skill은 거대한 지식 창고가 아니라 재현 가능한 작업법이다.

---

## Skill 구조

```text
pr-check/
├─ SKILL.md
├─ scripts/
├─ references/
└─ assets/
```

- `SKILL.md`: 언제·어떻게 수행하는지
- `scripts/`: 반복 실행할 결정적 절차
- `references/`: 필요할 때 읽는 지식
- `assets/`: 템플릿과 재사용 파일

필요한 것만 만든다.

---

## PR 검증 Skill 설계

입력:

- 기준 branch
- 프로젝트 종류
- 허용 시간

절차:

1. diff 범위 확인
2. 변경 파일과 가까운 테스트 실행
3. lint·typecheck 실행
4. 보안·회귀 리뷰
5. 결과와 미검증 항목 보고

파괴적 수정과 PR 게시에는 별도 승인을 요구한다.

---

## Skill 호출

- 명시 호출: `$skill-name`
- 설명에 따른 자동 선택
- Slash command 목록에서 사용 가능한 Skill 확인

실습에서는 같은 작업을 일반 프롬프트와 Skill로 각각 수행해 결과의 재현성·누락·시간 차이를 비교한다.

---

## Plugin

Plugin은 설치·배포할 수 있는 기능 묶음이다.

검토할 것:

- 제공하는 Skill·MCP·Hook·앱
- 요청 권한과 외부 서비스
- 설치 후 재시작·새 Chat 요구사항
- 조직 정책과 신뢰 출처
- 업데이트와 제거 방법

기능 이름만 보고 설치하지 않는다.

---

## MCP 연결 흐름

```powershell
codex mcp list
codex mcp add <name> -- <server-command>
codex mcp login <name>
```

연결 후 `/mcp`에서 확인:

- 서버 상태
- 사용 가능한 도구
- 인증 상태
- 읽기·쓰기 범위

정확한 인수는 현재 CLI의 `codex mcp --help`로 확인한다.

---

## 외부 도구 위험

- 과도한 OAuth 권한
- 의도하지 않은 쓰기·삭제
- 외부 문서에 포함된 악성 지시
- 민감한 저장소 정보의 외부 전송
- 오래된 세션과 토큰

처음에는 읽기 전용 도구와 샘플 데이터로 검증한다.

---

## WebMCP

WebMCP는 사이트가 브라우저 안에서 구조화된 도구를 제공하는 방식이다.

확인할 것:

- 현재 사이트와 도구 제공자
- 읽기·쓰기·결제 등 부작용
- 사용자 계정으로 실행되는 행동
- 실행 전 미리보기와 승인

페이지 텍스트의 지시와 신뢰된 도구 설명을 구분한다.

---

## 실습

1. `PR 검증` Skill을 만든다.
2. `$skill-name`으로 명시 호출한다.
3. 변경 파일과 테스트 결과가 정해진 형식으로 나오는지 확인한다.
4. 읽기 전용 MCP 또는 강사 제공 mock MCP를 연결한다.
5. 도구 목록과 권한을 기록하고 조회 한 번을 수행한다.

---

## 제출물

- Skill 디렉터리와 `SKILL.md`
- 일반 프롬프트 대비 Skill 결과 비교

- 실행 기록과 승인 판단
- 프롬프트 인젝션 대응 원칙
