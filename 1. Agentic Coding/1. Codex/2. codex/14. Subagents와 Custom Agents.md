# Subagents와 Custom Agents

독립 작업을 병렬화하고 결과를 통합하기

---

## 오늘의 목표

- 병렬화할 작업과 순차 작업을 구분한다.
- Subagent에게 좁고 독립적인 과제를 위임한다.
- 역할별 Custom agent를 정의한다.
- Worktree로 쓰기 충돌을 예방한다.

---

## 병렬화가 유리한 작업

- 서로 다른 영역의 코드 탐색
- 독립적인 테스트 설계
- 보안·접근성·성능 관점 리뷰
- 여러 대안 조사
- 긴 로그의 구간별 분석

같은 파일을 동시에 수정하거나 앞 단계 결과가 필요한 작업은 순차 실행이 낫다.

---

## 작업 분해 기준

좋은 Subagent 과제는:

- 결과물이 하나다.
- 입력과 범위가 분명하다.
- 다른 과제와 독립적이다.
- 읽기 전용으로도 가치가 있다.
- 완료·중단 조건이 있다.

“전체를 알아서 완성”은 위임이 아니라 책임 범위의 상실이다.

---

## 위임 예시

```text
탐색 agent:
- 예약 생성 요청의 route→DB 흐름만 조사
- 수정하지 않음
- 관련 파일·심볼·위험을 표로 보고

테스트 agent:
- 중복 예약과 정원 경쟁 조건의 테스트 공백 조사
- 수정하지 않음
- 재현 가능한 테스트 후보를 우선순위로 보고
```

메인 Chat은 두 결과를 코드로 교차 검증한다.

---

## 내장 역할과 Custom agent

일반적인 내장 역할:

- explorer: 읽기 중심 저장소 탐색
- worker: 구현과 수정
- default: 범용 작업

반복적으로 다른 성격이 필요하면 `.codex/agents/`에 Custom agent를 정의한다.

---

## Custom agent에 넣을 것

- 역할과 책임
- 읽을 범위와 수정 가능 범위
- 모델과 추론 수준
- Sandbox와 도구 제한
- 출력 형식
- 중단하고 메인에게 질문할 조건

예: 보안 리뷰 agent는 기본 읽기 전용, 코드 변경 금지, 근거 중심 Finding 출력.

---

## 권한 상속

Subagent는 메인 세션의 Sandbox·승인·도구 설정 영향을 받는다.

확인할 것:

- 위임 전 메인 권한 모드
- 각 Custom agent의 별도 제한
- MCP·Skill 사용 가능 범위
- 비대화형 실행에서 승인 요청이 실패하는 방식

병렬 agent 수가 늘어날수록 승인 출처를 더 주의 깊게 확인한다.

---

## Worktree와 쓰기 작업

병렬 쓰기가 필요하면 작업별 Worktree를 사용한다.

```text
Worktree A: UI 구현
Worktree B: API 테스트 보강
Main Chat: 계약 검토와 결과 통합
```

같은 파일을 수정해야 한다면 한 agent가 소유하고 다른 agent는 읽기 전용 리뷰를 수행한다.

---

## 결과 통합

메인 Chat이 확인할 것:

- agent별 전제와 코드 기준 시점
- 서로 충돌하는 결론
- 실제 파일과 테스트 근거
- 중복 작업과 누락된 경계
- 적용 순서와 충돌 위험

여러 agent가 같은 말을 했다는 사실은 독립된 증거가 아니다.

---

## 비용과 조정

병렬화의 비용:

- 토큰과 실행 시간
- 결과를 읽고 통합하는 시간
- 중복 탐색
- 권한 요청과 충돌 관리

작업이 작거나 강하게 의존하면 단일 agent가 더 빠르고 정확할 수 있다.

---

## 실습

예약 기능을 세 관점으로 조사한다.

1. explorer: 코드 흐름
2. test agent: 회귀 테스트 공백
3. security agent: 인증·인가 위험

조건:

- 세 agent 모두 읽기 전용
- 정해진 출력 형식 사용
- 메인 Chat에서 중복 제거와 근거 확인
- 구현은 통합 계획 승인 후 하나의 Worktree에서 수행

---

## 평가 체크

- [ ] 과제가 독립적이고 범위가 좁다.
- [ ] 권한과 수정 가능 범위를 명시했다.
- [ ] 결과를 실제 코드로 교차 검증했다.
- [ ] 병렬 쓰기 충돌을 예방했다.
- [ ] 단일 agent 대비 이점과 비용을 설명했다.
