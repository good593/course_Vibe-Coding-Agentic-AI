# Hooks·codex exec·GitHub Action·SDK

대화형 작업을 반복 가능한 자동 검증으로 확장하기

---

## 오늘의 목표

- Hook과 Skill·Rules의 차이를 구분한다.
- `codex exec`를 비대화형으로 실행한다.
- JSONL과 output schema로 결과를 기계가 읽게 만든다.
- GitHub Action과 Codex 플랫폼 구성요소의 역할을 설명한다.

---

## 자동화 단계

| 단계 | 도구 | 목적 |
|---|---|---|
| 대화형 반복 | Skill | 사람이 시작하는 표준 절차 |
| 이벤트 반응 | Hook | 도구 호출 전후의 기계적 처리 |
| 스크립트 실행 | `codex exec` | 비대화형 단일 작업 |
| CI/CD | GitHub Action | 저장소 이벤트 기반 실행 |
| 제품 통합 | SDK·App Server | Codex를 애플리케이션에 내장 |

---

## Hooks

Hook은 특정 수명주기 이벤트에 반응한다.

- `PreToolUse`: 도구 실행 전 검사
- `PostToolUse`: 실행 결과 기록·검사
- `Stop`: 작업 종료 시 후처리

사용 예:

- 위험 명령 정책 검사
- 변경 후 formatter 실행
- 종료 시 테스트 결과 수집

Hook은 신뢰할 수 있는 코드만 사용한다.

---

## Hook 설계 원칙

- 빠르고 결정적으로 실행
- 입력과 종료 코드 계약 명확화
- 실패 시 안전하게 중단
- 비밀값을 로그로 출력하지 않기
- 프로젝트 설정과 사용자 설정의 출처 표시

`/hooks`에서 현재 활성 Hook과 출처를 확인한다.

---

## codex exec

비대화형 실행은 CI·스크립트·배치 작업에 적합하다.

```powershell
codex exec "현재 변경을 리뷰하고 정확성 문제만 보고해줘"
```

자동화에서는 다음을 명시한다.

- 작업 디렉터리
- Sandbox와 승인 정책
- 제한 시간
- 출력 형식
- 실패 처리

---

## JSONL 출력

```powershell
codex exec --json "현재 변경을 리뷰해줘"
```

활용:

- 실행 이벤트 스트리밍
- 로그 저장
- 후속 도구 파싱
- 실패 지점 분석

사람이 읽는 최종 문장만 정규식으로 파싱하지 않는다.

---

## Output schema

구조화된 출력 예:

```json
{
  "type": "object",
  "properties": {
    "result": { "type": "string" },
    "findings": { "type": "array" },
    "tests": { "type": "array" }
  },
  "required": ["result", "findings", "tests"]
}
```

Schema 검증 실패를 성공으로 처리하지 않는다.

---

## GitHub Action

Codex Action을 사용할 수 있는 예:

- PR 코드 리뷰
- 릴리스 체크
- 반복 마이그레이션 보조
- 품질 기준 미달 시 차단

필수 설계:

- 최소 `permissions`
- 비밀값과 코드 분리
- 신뢰할 수 없는 PR 입력 주의
- timeout과 실패 폐쇄
- 사람이 검토할 결과물

---

## 플랫폼 구성요소

| 구성요소 | 용도 |
|---|---|
| Codex SDK | 코드에서 Codex 실행과 스레드를 제어 |
| App Server | 클라이언트가 Codex 기능을 사용하도록 서버 인터페이스 제공 |
| MCP Server | Codex가 호출할 외부 도구와 데이터를 제공 |

“Codex를 실행하는 것”과 “Codex에게 도구를 제공하는 것”을 구분한다.

---

## 강사 시연

1. 읽기 전용 `codex exec` 리뷰 실행
2. JSONL 로그 저장과 이벤트 확인
3. schema로 Finding 형식 제한
4. 실패 exit code 처리
5. 같은 작업을 GitHub Action workflow로 옮긴 구조 설명

---

## 실습

자동 PR 검증 흐름을 만든다.

1. 변경 파일과 가까운 테스트 실행
2. `codex exec`로 정확성 리뷰
3. JSONL 로그와 구조화 결과 저장
4. Finding이 기준 이상이면 실패
5. GitHub Action 초안 작성

실제 PR 코멘트 게시는 강사 확인 후 선택적으로 수행한다.
