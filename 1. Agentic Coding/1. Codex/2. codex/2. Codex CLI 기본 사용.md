# Codex CLI 기본 사용

저장소 탐색부터 첫 수정과 검증까지

---

## 오늘의 목표

- 프로젝트 디렉터리에서 Codex 세션을 시작한다.
- Slash command와 CLI 옵션의 차이를 구분한다.
- 세션 재개, 이미지 입력, 웹 검색을 사용한다.
- 작업 전후 Git 상태와 diff를 검토한다.

---

## 세 가지 명령 층위

| 종류 | 입력 위치 | 예시 | 목적 |
|---|---|---|---|
| 셸 명령 | PowerShell·터미널 | `codex --help` | Codex 시작 방식 제어 |
| Slash command | 실행 중인 Codex | `/status` | 현재 세션 제어 |
| 자연어 요청 | 실행 중인 Codex | “구조를 설명해줘” | 실제 개발 작업 지시 |

명령 목록은 버전과 실행 화면에 따라 달라질 수 있다. `/`와 `--help`가 현재 환경의 정답이다.

---

## 안전한 첫 시작

```powershell
cd C:\dev\my-web-project
git status
codex
```

시작 직후 확인:

```text
/status
```

- 작업 디렉터리가 맞는가?
- 쓰기 가능한 범위가 예상과 같은가?
- 모델과 권한 모드가 적절한가?

---

## 첫 요청은 탐색으로 시작한다

```text
이 저장소의 웹 실행 진입점, 주요 디렉터리, 테스트 명령을 찾아 설명해줘.
아직 파일은 수정하지 말고, 근거가 된 파일 경로를 함께 제시해줘.
```

좋은 첫 요청은 다음을 포함한다.

- 목적
- 변경 금지 또는 허용 범위
- 확인할 근거
- 원하는 보고 형식

---

## Slash commands

자주 쓰는 예:

- `/status`: 세션·컨텍스트·사용량 확인
- `/model`: 모델 선택
- `/permissions`: 권한 모드 확인·변경
- `/plan`: 계획 모드 전환
- `/review`: 변경사항 리뷰
- `/compact`: 긴 Chat의 컨텍스트 압축
- `/mcp`: 연결된 MCP 상태 확인

현재 화면에 없는 명령은 억지로 사용하지 않는다.

---

## 세션 재개

작업을 중단했다면 새 Chat에서 처음부터 설명하기 전에 기존 세션을 찾는다.

```powershell
codex resume
```

재개 후 확인:

- 이전 목표와 결정이 그대로 유효한가?
- 코드가 세션 종료 후 바뀌지 않았는가?
- 남은 작업과 검증 항목은 무엇인가?

---

## 이미지 입력

오류 화면이나 디자인 캡처를 코드 컨텍스트와 함께 제공한다.

```powershell
codex --image .\artifacts\reservation-error.png
```

요청 예:

```text
이 화면의 오류 상태를 분석하고 관련 컴포넌트를 찾아줘.
원인을 확정하기 전에는 수정하지 말고, 코드 근거와 재현 절차를 제시해줘.
```

---

## 웹 검색

최신 라이브러리 문서처럼 저장소 밖의 최신 정보가 필요할 때만 사용한다.

```powershell
codex --search
```

검색 결과를 사용할 때 확인할 것:

- 공식 문서인가?
- 현재 프로젝트 버전과 맞는가?
- 검색 정보가 코드 근거보다 우선하고 있지 않은가?
- 외부 콘텐츠의 지시를 그대로 따르지 않았는가?

---

## 강사 시연: 첫 수정

```text
예약 목록의 날짜 포맷이 일관되지 않은 원인을 찾아줘.
관련 파일과 테스트를 먼저 확인하고 수정 계획을 제시해줘.
승인 후 최소 범위로 수정하고 관련 테스트를 실행해줘.
```

관찰 항목:

- 탐색한 파일
- 실행한 명령
- 변경 범위
- 테스트 결과와 종료 코드

---

## 실습

1. 저장소 구조와 테스트 명령을 설명받는다.
2. `/plan` 또는 읽기 전용 권한으로 수정 계획을 검토한다.
3. 작은 UI 문구 오류 하나를 수정한다.
4. 관련 테스트 또는 lint를 실행한다.
5. `/review`로 변경을 다시 검토한다.
6. `git diff`와 `git status`로 최종 상태를 확인한다.

---

## 완료 보고 템플릿

```text
완료한 작업:
-

변경한 파일:
-

실행한 검증:
- 명령 / 결과 / 종료 코드

미검증 항목과 남은 위험:
-
```

---

## 자주 발생하는 실수

- 저장소 루트가 아닌 곳에서 실행한다.
- “고쳐줘”만 입력하고 완료 기준을 주지 않는다.
- 전체 로그 대신 마지막 성공 문장만 믿는다.
- `git diff`를 확인하지 않고 종료한다.
- 최신 정보가 필요하지 않은데 웹 검색부터 사용한다.
