# Codex IDE 확장

열린 코드와 선택 영역을 정확한 컨텍스트로 사용하기

---

## 오늘의 목표

- IDE 확장에서 Codex를 연결하고 상태를 확인한다.
- 열린 파일과 선택 영역을 의도적으로 컨텍스트에 포함한다.
- 이미지와 오류 메시지를 코드와 함께 전달한다.
- 변경 diff를 검토하고 큰 작업을 Cloud에 위임한다.

---

## IDE가 잘 맞는 작업

- 현재 보고 있는 함수 설명
- 선택한 코드의 국소 리팩터링
- 타입 오류나 lint 오류 수정
- 컴포넌트와 인접 테스트 동시 변경
- 생성된 diff를 코드 옆에서 검토

저장소 전체를 오래 탐색하거나 여러 작업을 병렬화할 때는 App·CLI·Cloud가 더 적합할 수 있다.

---

## 컨텍스트의 우선순위

1. 명시적으로 선택한 코드
2. 열린 파일과 현재 편집 위치
3. 프롬프트에 적은 파일·심볼 경로
4. Codex가 저장소에서 탐색한 관련 코드

“알아서 찾겠지”보다 **관련 범위와 제외 범위를 명시**하는 편이 안전하다.

---

## 좋은 IDE 요청

```text
선택한 함수의 중복 조건문을 정리해줘.

제약:
- 공개 함수 시그니처는 바꾸지 않는다.
- 현재 파일과 인접 테스트만 수정한다.
- 동작 변경이 필요한 경우 먼저 질문한다.

완료 기준:
- 관련 단위 테스트 통과
- 변경 이유와 미검증 항목 보고
```

---

## 이미지와 오류 화면

다음 세 가지를 함께 제공하면 진단 품질이 좋아진다.

- 화면 캡처: 실제 증상
- 선택한 컴포넌트: 예상 관련 코드
- 재현 절차·콘솔 오류: 실행 근거

이미지에서 추론한 내용과 코드로 확인한 사실을 구분하도록 요청한다.

---

## 변경 검토

diff에서 확인할 것:

- 요청 범위 밖 파일이 바뀌었는가?
- 기존 컴포넌트·유틸을 재사용했는가?
- 정상·오류·빈 상태가 유지되는가?
- 테스트가 실제 변경 동작을 검증하는가?
- 주석으로 문제를 숨기거나 타입을 우회하지 않았는가?

---

## Cloud로 위임할 때

다음 정보를 넘긴다.

- 기준 브랜치와 대상 저장소
- 목표와 비목표
- 실행해야 할 테스트
- 변경하면 안 되는 경로
- 결과를 적용할 조건

Cloud 결과는 자동 정답이 아니다. 로컬에 적용하기 전에 diff와 테스트를 다시 확인한다.

---

## 강사 시연

1. 예약 카드 컴포넌트를 연다.
2. 날짜 표시 함수만 선택한다.
3. 제약과 완료 기준을 포함해 리팩터링을 요청한다.
4. diff에 인라인 피드백을 남긴다.
5. 수정 후 테스트 결과를 확인한다.

---

## 실습

다음 중 하나를 선택한다.

- 선택 영역의 타입 안정성 개선
- 오류 화면을 기반으로 빈 상태 구현
- 반복되는 JSX를 기존 컴포넌트로 교체

필수 증거:

- 사용한 컨텍스트 목록
- 수정 전 계획
- 최종 diff
- 테스트 또는 lint 결과
- Codex 제안을 거절하거나 수정한 지점

---

## 완료 체크

- [ ] 선택 영역과 열린 파일이 의도한 범위다.
- [ ] 변경 전 제약과 완료 기준을 전달했다.
- [ ] diff의 모든 줄을 검토했다.
- [ ] 실행한 검증과 실행하지 못한 검증을 구분했다.
- [ ] 큰 작업을 로컬에서 계속할지 Cloud에 맡길지 설명할 수 있다.
