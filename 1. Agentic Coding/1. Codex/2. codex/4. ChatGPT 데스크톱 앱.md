# ChatGPT 데스크톱 앱에서 Codex 사용하기

Projects·Chats·통합 터미널·Git 변경을 한곳에서 조정하기

---

## 오늘의 목표

- 웹 저장소를 Project로 등록한다.
- 목적에 따라 Chat을 분리한다.
- 통합 터미널과 Git 변경 화면을 사용한다.
- 여러 저장소 작업에서 경계와 완료 증거를 관리한다.

---

## Project와 Chat

- Project: 저장소와 실행 환경을 묶는 작업 공간
- Chat: 하나의 목표와 의사결정 흐름

권장 분리:

- 기능 구현 Chat
- 버그 조사 Chat
- 테스트 보강 Chat
- 코드 리뷰 Chat

한 Chat에 관련 없는 목표를 계속 추가하면 컨텍스트와 검증 범위가 흐려진다.

---

## 여러 저장소를 다룰 때

프런트엔드와 백엔드 저장소를 함께 작업한다면 먼저 경계를 선언한다.

```text
frontend: 예약 폼과 API client만 수정 가능
backend: 예약 생성 endpoint와 테스트만 수정 가능
공통 계약: docs/reservation-api.md를 기준으로 사용
DB migration과 배포 설정은 수정하지 않음
```

저장소별 명령과 완료 조건도 분리한다.

---

## 통합 터미널

자주 사용하는 작업을 직접 확인한다.

```powershell
git status
npm test
npm run lint
npm run dev
```

Codex가 실행했다는 문장보다 다음 증거를 본다.

- 실제 명령
- 종료 코드
- 실패한 테스트 이름
- 생략되거나 중단된 단계

---

## Git 변경 화면

- 파일별 diff 확인
- 변경 구간별 stage 또는 되돌리기
- 인라인 코멘트로 재수정 요청
- 의미 단위 commit
- branch push와 PR 생성

되돌리기는 사용자 작업을 지울 수 있으므로 대상 파일과 변경 소유자를 먼저 확인한다.

---

## 강사 시연

1. 예약 서비스 Project를 연다.
2. `API 계약 확인` Chat과 `예약 폼 구현` Chat을 분리한다.
3. 터미널에서 테스트를 실행한다.
4. diff에 “오류 메시지는 기존 컴포넌트를 사용”이라고 코멘트한다.
5. 수정 결과를 다시 검증한다.

---

## 실습: 두 저장소 연결 작업

목표: 예약 인원 제한 오류를 UI에 표시한다.

1. 프런트·백의 관련 코드를 각각 탐색한다.
2. API 오류 계약을 표로 정리한다.
3. 저장소별 수정 계획과 테스트를 승인한다.
4. 통합 터미널에서 검증한다.
5. 최종 diff를 저장소별로 검토한다.

---

## 제출물

- Project와 Chat 분리 구조 캡처
- 프런트·백 변경 파일 목록
- 실행 명령과 결과
- 저장소별 diff 검토 기록
- 미검증 통합 구간

완료 기준은 “코드가 생성됨”이 아니라 “두 저장소의 계약과 검증 결과가 일치함”이다.
