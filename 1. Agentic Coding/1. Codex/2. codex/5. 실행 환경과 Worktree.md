# 실행 환경과 Worktree

Local·Worktree·Cloud·Remote를 안전하게 선택하기

---

## 오늘의 목표

- 네 실행 환경의 코드 위치와 격리 수준을 구분한다.
- Git Worktree로 병렬 작업을 격리한다.
- Cloud 결과를 검토하고 로컬에 적용한다.
- Handoff와 Remote의 이동 범위를 설명한다.

---

## 환경 비교

| 환경 | 코드가 있는 곳 | 잘 맞는 작업 | 주의점 |
|---|---|---|---|
| Local | 현재 checkout | 즉시 확인할 작은 작업 | 사용자 변경과 충돌 가능 |
| Worktree | 별도 Git checkout | 독립 병렬 작업 | branch·동일 파일 충돌 관리 |
| Cloud | 호스팅 격리 환경 | 장기 실행·백그라운드 작업 | 환경 차이와 적용 전 재검증 |
| Remote | 연결된 다른 호스트 | 원격 지시·승인·검토 | 실제 실행 호스트 확인 |

---

## Worktree가 필요한 이유

하나의 checkout에서 두 에이전트가 동시에 수정하면:

- 같은 파일을 덮어쓸 수 있다.
- 테스트 결과의 기준이 바뀔 수 있다.
- 어떤 변경이 어느 작업의 결과인지 흐려진다.

Worktree는 저장소 메타데이터를 공유하면서 작업 디렉터리를 분리한다.

---

## Worktree 작업 원칙

- 한 Worktree에는 하나의 주요 목표
- 같은 파일을 여러 Worktree에서 동시에 수정하지 않기
- 시작 기준 branch 기록
- 각 Worktree에서 독립 테스트
- 합치기 전에 diff와 충돌 영향 검토

`git status`와 현재 branch·worktree 위치를 자주 확인한다.

---

## Local ↔ Worktree Handoff

Handoff는 Chat과 Git 상태를 다른 checkout으로 옮겨 계속 작업하는 흐름이다.

확인할 것:

- 이동 전후 Chat이 연결된 위치
- branch와 uncommitted changes
- `.gitignore` 파일의 이동 여부
- 개발 서버와 로컬 데이터의 위치

Handoff 후에도 기존 터미널이 어느 디렉터리를 보고 있는지 다시 확인한다.

---

## Cloud로 맡길 때

Cloud 환경에 명시할 항목:

- setup 과정과 의존성 설치 방법
- 기준 branch와 작업 범위
- 필요한 환경 변수와 비밀값의 취급
- 네트워크 사용 여부
- 완료 시 실행할 검증

Cloud에서 통과한 테스트가 로컬·운영 환경에서도 같다는 보장은 없다.

---

## Remote 사용

Remote는 코드를 휴대전화로 복사하는 기능이 아니라 연결된 컴퓨터의 Codex를 제어하는 방식이다.

- 실제 저장소와 Worktree는 연결된 호스트에 남는다.
- 모바일에서 프롬프트·추가 지시·승인·검토를 수행할 수 있다.
- 승인 전 대상 호스트와 실행 위치를 확인한다.

---

## 강사 시연

동시에 두 작업을 시작한다.

- Worktree A: 예약 폼 유효성 검사
- Worktree B: 예약 API 테스트 보강

각각 테스트한 뒤 변경 파일이 겹치는지 확인하고, 한 작업을 Local로 Handoff한다.

---

## 실습: 환경 선택과 격리

1. 현재 Local 변경을 기록한다.
2. 새 Worktree에서 작은 버그 수정을 시작한다.
3. 별도 Worktree 또는 Cloud에 테스트 조사를 맡긴다.
4. 결과의 diff와 테스트를 각각 검토한다.
5. 적용 순서와 충돌 해결 방식을 작성한다.

---

## 완료 체크

- [ ] 각 Chat의 실행 위치를 설명할 수 있다.
- [ ] 사용자 Local 변경을 침범하지 않았다.
- [ ] 각 환경에서 테스트를 독립 실행했다.
- [ ] 결과 적용 전에 diff와 충돌을 확인했다.
- [ ] Remote 승인 시 실제 호스트를 확인했다.
