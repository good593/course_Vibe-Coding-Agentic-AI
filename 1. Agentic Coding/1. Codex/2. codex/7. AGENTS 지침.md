# AGENTS.md

저장소의 개발 규칙을 Codex가 계속 따르게 만들기

---

## 오늘의 목표

- 프롬프트와 `AGENTS.md`의 역할을 구분한다.
- 저장소에 필요한 지침을 작성한다.
- 루트·하위 디렉터리·override의 적용 범위를 확인한다.
- 코드 리뷰 규칙을 저장소 지침과 연결한다.

---

## 언제 AGENTS.md를 사용하는가

| 정보 | 적합한 위치 |
|---|---|
| 이번 작업만의 요구사항 | 현재 프롬프트 |
| 저장소 공통 명령과 규칙 | 루트 `AGENTS.md` |
| 특정 하위 프로젝트 규칙 | 하위 `AGENTS.md` |
| 일시적으로 더 구체적인 지침 | `AGENTS.override.md` |
| 개인의 모든 저장소 기본값 | 전역 지침 |

일회성 요청을 모두 영구 지침으로 만들지 않는다.

---

## 적용 원리

Codex는 작업 위치를 기준으로 지침 파일을 읽고, 더 가까운 위치의 구체적인 지침을 적용한다.

예시:

```text
repo/
├─ AGENTS.md
├─ frontend/
│  └─ AGENTS.md
└─ backend/
   └─ AGENTS.override.md
```

수정할 파일이 어느 지침 범위에 속하는지 먼저 확인한다.

---

## 좋은 AGENTS.md의 구성

```markdown
# Repository Guide

## Architecture
## Build and test commands
## Code style
## Security constraints
## Definition of done
## Code Review Rules
```

간결하고 실행 가능하며 현재 저장소에서 확인할 수 있어야 한다.

---

## 명령은 정확하게

나쁜 예:

```text
테스트를 잘 실행한다.
```

좋은 예:

```text
- 변경 파일과 가까운 단위 테스트를 먼저 실행한다.
- 전체 검증은 `npm run lint && npm test`이다.
- E2E를 실행하지 못하면 이유를 최종 보고에 남긴다.
```

---

## 완료 조건과 금지 사항

```markdown
## Definition of done
- 정상·로딩·빈 상태·오류 상태를 처리한다.
- 관련 테스트와 lint가 통과해야 한다.
- 실행하지 못한 검증을 명시한다.

## Do not
- `.env`와 실제 자격증명을 커밋하지 않는다.
- 승인 없이 DB migration이나 배포 설정을 변경하지 않는다.
- 오류를 `any` 또는 검사 비활성화로 숨기지 않는다.
```

---

## Code Review Rules

웹 프로젝트에 유용한 규칙:

- 인증과 인가를 혼동하지 않았는가?
- 사용자 입력을 서버에서도 검증하는가?
- 접근성과 키보드 조작이 유지되는가?
- 오류에 비밀값이나 내부 정보가 노출되지 않는가?
- 테스트가 실패 경로와 회귀를 검증하는가?

저장소 특화 규칙만 남기고 일반론은 줄인다.

---

## 강사 시연

1. `/init`으로 초안을 만든다.
2. 실제 `package.json`에서 명령을 확인한다.
3. 존재하지 않는 명령과 추상적 문장을 제거한다.
4. `frontend/AGENTS.md`에 UI 규칙을 추가한다.
5. Codex에게 현재 적용되는 지침을 근거와 함께 설명하게 한다.

---

## 실습

예약 서비스 저장소에 다음을 작성한다.

- 구조 설명과 핵심 디렉터리
- build·lint·test 명령
- 코드 스타일과 재사용 원칙
- 보안상 금지 사항
- 완료 조건
- 리뷰 규칙 3개 이상

그 후 일부러 규칙과 충돌하는 요청을 주고 Codex의 반응을 확인한다.

---

## 검증 질문

- 지침의 모든 명령이 실제로 존재하는가?
- 경로별 규칙이 충돌하지 않는가?
- 너무 긴 배경 설명이 핵심 규칙을 가리지 않는가?
- 사람이 확인해야 할 승인 조건이 명시되어 있는가?
- 새 팀원이 읽어도 같은 방식으로 검증할 수 있는가?
